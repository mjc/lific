Lific is one executable. Download a prebuilt binary if you want it running in under a minute, or install it with Cargo if you already have a Rust toolchain. Either way you get the same program with the web UI built in.

| Way in | What you need | Good when |
| --- | --- | --- |
| Release binary | Nothing. The download runs as it is. | You want the fastest path, or the machine has no Rust toolchain. |
| `cargo install lific` | Rust 1.99 or later, and a few minutes to compile. | You already use Cargo, or your platform has no release binary. |
| Source build | A checkout, plus [devenv](https://devenv.sh/) or Cargo. | You are changing Lific itself, or you want to build the exact tree you are reading. |

A container image is not published anywhere, but the repository's Dockerfile builds one. [Self-hosting](/docs/self-hosting#containers) covers it.

## Download a release binary

Every release publishes five binaries and a `sha256sums.txt` on the [releases page](https://github.com/VoidNullable/lific/releases).

| Platform | File |
| --- | --- |
| Linux x86_64 | `lific-linux-x86_64` |
| Linux aarch64 | `lific-linux-aarch64` |
| macOS Intel | `lific-macos-x86_64` |
| macOS Apple silicon | `lific-macos-aarch64` |
| Windows x86_64 | `lific-windows-x86_64.exe` |

On any other operating system or architecture, use Cargo.

On Linux, download the binary and the checksum file, verify the download, then put it on your `PATH`:

```bash
curl -LO https://github.com/VoidNullable/lific/releases/latest/download/lific-linux-x86_64
curl -LO https://github.com/VoidNullable/lific/releases/latest/download/sha256sums.txt
sha256sum --ignore-missing -c sha256sums.txt
chmod +x lific-linux-x86_64
sudo mv lific-linux-x86_64 /usr/local/bin/lific
```

macOS has no `sha256sum`. Download the same way, then check with `shasum`:

```bash
shasum -a 256 --ignore-missing -c sha256sums.txt
```

`--ignore-missing` tells both tools to check only the file you downloaded, instead of failing on the four binaries you did not. The line for your file should end in `OK`.

A binary downloaded with `curl` runs as it is. The macOS binaries are not signed, so if you download one with a browser instead, macOS refuses to open it until you clear the quarantine flag the browser set: `xattr -d com.apple.quarantine lific-macos-aarch64`.

On Windows, compare the hash in PowerShell:

```powershell
$expected = (Select-String -Path sha256sums.txt -Pattern 'lific-windows-x86_64\.exe').Line.Split(' ')[0]
$actual   = (Get-FileHash lific-windows-x86_64.exe -Algorithm SHA256).Hash
if ($actual -ieq $expected) { "checksum ok" } else { "checksum MISMATCH" }
```

Then rename the file to `lific.exe` and put it in a directory on your `PATH`. [Windows](/docs/windows) covers the rest of that platform, including keeping the server running.

A mismatch means the file is not the one that was released. Delete it and download it again rather than running it.

## Install with Cargo

```bash
cargo install lific
```

Lific v3 compiles its Topcoat pages and browser assets into the executable, so Cargo installs include the same interface as the release binaries. Compiling takes several minutes and needs Rust 1.99 or later; install Rust from [rustup.rs](https://rustup.rs) if `cargo` is missing. On Windows, Cargo also needs the Visual Studio C++ build tools, which [Windows](/docs/windows#or-install-with-cargo) explains.

Cargo puts the binary in `~/.cargo/bin` (`%USERPROFILE%\.cargo\bin` on Windows), which rustup has already added to your `PATH`.

## Check the install

```bash
lific --version
```

If the shell cannot find `lific`, the directory you put it in is not on your `PATH`.

## Build from source

Source builds run through the repository's [devenv](https://devenv.sh/) environment, which pins the Rust toolchain and cross-compilation tools. Topcoat pages, JavaScript, CSS, and the browser runtime are compiled into the binary from `src/topcoat`. The environment also provides the tools for browser tests and documentation work.

```bash
git clone https://github.com/VoidNullable/lific
cd lific
devenv allow
devenv shell
# inside the devenv shell:
devenv tasks run lific:debug-build
```

That writes `target/debug/lific`.

Release binaries use the `dist` Cargo profile and a devenv profile per operating system. These are the commands the release workflow runs:

```bash
devenv --profile release-linux tasks run lific:release:x86_64-unknown-linux-gnu
devenv --profile release-linux tasks run lific:release:aarch64-unknown-linux-gnu
devenv --profile release-darwin tasks run lific:release:x86_64-apple-darwin
devenv --profile release-darwin tasks run lific:release:aarch64-apple-darwin
devenv --profile release-windows-msvc tasks run lific:release:x86_64-pc-windows-msvc
```

Each writes `target/<target-triple>/dist/lific` (`lific.exe` for Windows). The two Linux targets and the Windows target build on Linux; the macOS targets need a Mac.

### Without devenv

On systems other than NixOS and nix-darwin, plain Cargo can build the same embedded interface:

```bash
cargo build --release --locked
```

Both debug and release builds embed the Topcoat interface. The executable serves its pages and assets from any working directory. On NixOS and nix-darwin, use the repository's devenv workflow to obtain the correct toolchain and libraries.

## Deploying v3 and rolling back

Before replacing an existing installation, save its executable as
`lific.previous`, or retain the previous container image by digest or as
`lific:previous`. Stop the instance and use that previous executable to create
`lific-before-v3.tar.gz` with `./lific.previous dump --out lific-before-v3.tar.gz`;
keep the archive and instance
configuration outside the active data directory. Deploy v3 using the same
configuration and data locations, then check health, sign-in, and project pages.

To roll back, stop v3 and return the service to the saved executable path or
previous image reference. V3 supports database schema 58; a previous release
that supports an earlier schema refuses the upgraded database. In that case,
run `./lific.previous restore lific-before-v3.tar.gz --force`
with the original instance options before restarting it. The snapshot includes
the database and attachments; restoring it removes changes made after it was
created, so preserve a separate v3 dump first if those changes need recovery.
Check health and project pages again after restarting the previous release.

The [v3 migration guide](https://github.com/VoidNullable/lific/blob/master/docs/topcoat-migration.md#deployment-and-rollback)
explains the migration checksum checks, rollback sequence, and pinned Topcoat
upgrade policy.
